# Making this repository readable by a person

Deferred on purpose, and written down so it is not lost. Raised by the
language's author 2026-09-24: the code was written by a reader who can hold
the whole of it at once, and a person cannot. Nothing here is about what the
code *does*; it is about someone finding their way into it.

Do this when the applications in flight (`apps/markdown`, `apps/git`,
`apps/tui`, `lib/term`) have landed — a reorganisation and four
directory-creating agents at once would be a merge for no reason.

## What is actually missing

The house style is already "comments explain *why*, in full sentences", and
the decision records are thorough. The gaps are orientation and shape, not
prose:

  - **No map.** A newcomer opening `src/` meets 20,000 lines across a dozen
    files with no statement of what the pipeline is or which file owns which
    stage. `README.md` describes the language; nothing describes the
    compiler as a program.
  - **No index to `docs/`.** There are ~20 decision records with no list of
    them, no order to read them in, and no note of which are superseded
    (several are: `stdlib-decision.md` §"three features waiting on one
    mechanism" was overtaken by the sort/map-key work, and the closures
    record rewrote itself once).
  - **`src/lower.rs` is ~7,000 lines.** It is the typechecker and the
    lowerer fused on purpose (`README.md` says why, and the reason is good),
    but one file is not the only way to keep them in step. It has natural
    seams: declaration checking, expression lowering, statement lowering,
    the builtin methods, privacy, refcount placement.
  - **Nothing says how to work on it.** How to run one corpus test, how to
    add one, what each of the 17 gates is for, what to do when the formatter
    gate fails, how the oracle works, why `corpus/core/*.out` must never be
    generated by the compiler under test.
  - **Public library surfaces are uneven.** Some `lib/*.m31` modules open
    with an API list (`io`, `os`, `math`); others make the reader find the
    `pub` declarations themselves.
  - **No directory-level orientation.** `runtime/`, `corpus/`, `bench/`,
    `apps/` each deserve a paragraph saying what is in them and what the
    rules are.

## The plan, in order

1. **A map of the compiler**: one document walking a program from source
   text to emitted C, naming the file that owns each stage and the one or
   two ideas that make it work (type interning, the fused check-and-lower,
   monomorphisation before lowering, refcount placement, the vtable in the
   object header). Half a page per stage, not a design record.
2. **`docs/README.md`**: every document, one line each, grouped as *start
   here*, *decisions*, *reference*, with superseded ones marked and the
   thing that superseded them named.
3. **A contributor guide**: the gates, the corpus, the oracle, how to add a
   test of each kind, the rules that are easy to break (the runtime is a
   separate translation unit; `.out` files are hand-written; never iterate a
   HashMap to produce output).
4. **Split `src/lower.rs`** along its existing seams into a `lower/`
   directory, mechanically, with no behaviour change — the gates are exactly
   the safety net that makes this safe to do. `consts.rs` and `hold.rs` are
   already there, so the pattern exists.
5. **A README per directory**: `src/`, `runtime/`, `lib/`, `corpus/`,
   `bench/`, `apps/`.
6. **An API header per `lib/` module**, in the shape `io` and `os` already
   use: what it is for, the surface in one block, and the decisions a caller
   needs to know.
7. **A last pass over the doc comments on public declarations**, which is
   where a reader looks first and where the coverage is thinnest.

## What not to do

  - Do not add comments that restate the code. The existing ones earn their
    place by saying *why*, and a wave of "increments the counter" would
    dilute them.
  - Do not reformat or rename for taste. Every rename invalidates a decision
    record that quotes the old name.
  - Do not split a file that has no seam. `lower.rs` has them; `emit_c.rs`
    largely does not.
